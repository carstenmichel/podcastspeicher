- (note) Input: brainstorm intent (brainstorm-podcast-backup-2026-08-29/brainstorm-intent.md) + README-notes.md; greenfield repo, no existing code; rich pre-sorted input, direct extraction
- (decision) Slug podcast-backup from source folder; spec folder _bmad-output/specs/spec-podcast-backup
- (decision) Why = pain: podcast owners prune feeds so feed is not a durable archive; late subscribers cannot get unlisted episodes; backup must outlive app and feed, making the app a replaceable appliance
- (capability) CAP-1 (MUST) mirror new episodes to disk on ~6h poll: intent fetch RSS of each subscribed show each poll, download episodes not yet in registry; success new episode on disk within one poll cycle, recorded GUID not re-downloaded
- (capability) CAP-2 (MUST) permanent archive: never delete or overwrite any file on disk; success all previously downloaded episode files survive repeated polls with feed churn
- (capability) CAP-3 (MUST) human-readable archive: folders by podcast name + date, per-podcast podcast.md registry with episode GUIDs; success with container stopped user can browse folders, read podcast.md, play episode from file path (kill drill)
- (capability) CAP-4 (MUST) subscription management: user adds/removes shows by RSS feed URL on the config page; success add starts mirroring next poll, remove stops downloads but leaves files on disk
- (capability) CAP-5 (SHOULD) fleet status: user sees per-show last fetch time, episode count, disk usage; success values after a poll match actual last fetch, count, usage
- (capability) CAP-6 (SHOULD) poll interval override: user overrides default ~6h interval; success changing interval changes subsequent fetch cadence
- (capability) CAP-7 (MUST) README truncation warning: prominent callout near top that feeds cap ~last 20-50 episodes so late subscribers cannot catch up; success new user sees warning before adding shows
- (constraint) Single Go binary in small distroless Docker image, near-zero idle resources (confirmed architecture)
- (constraint) Config page is a single embedded HTML document served by the Go binary via go:embed; no React, no Node toolchain
- (constraint) Per-podcast podcast.md Markdown registry (chosen over central registry file) is the poll dedupe ledger; recorded episode GUIDs drive dedupe
- (constraint) v1 dedupe policy prefer duplicates over gaps: download when seen, tolerate a handful of duplicates per podcast; sha256 content dedupe is a later release
- (constraint) On-disk archive is plain files + Markdown only, no proprietary or binary formats, so it stays usable (grep, Obsidian, any reader) without the app
- (decision) Non-goals: no UI playback, no React SPA, no static-site generation, no search corpus; v1 excludes feed 404/rate-limit special handling (failed fetch waits for next poll) and sha256 content dedupe (later-release backlog)
- (decision) Success signal = kill drill: container stopped, user browses folders, reads a podcast.md, plays an episode from its file path; archive fully legible without app or feed running
- (assumption) Removing a show stops future downloads but leaves its files on disk (consequence of the never-delete property; input did not state remove semantics explicitly)
- (question) Is scope a personal backup of the operator's own subscriptions, and do feed-host terms of service / copyright need addressing (e.g. in the README)? Input silent.
- (question) Config page exposure: unauthenticated on a trusted/local network, or does it need access control? Input silent on auth.
